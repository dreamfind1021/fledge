# resume-note — 離場筆記

## 這個 skill 的定位

只做「下次接續」這一件事：不寫 Google Sheet、不產技術版／非技術版雙版本工作日誌、不記週報。

**刻意不攔截，但機制本身要做。** 逼使用者停下來才寫筆記這條路試過會被敷衍——連續幾天下來，敷衍的筆記比沒有筆記更糟。所以換個方向：**AI 根據這個 session 做過什麼自己寫一版**，不要人動手。目前由使用者主動叫（或 AI 在收工時主動提），不攔截使用者收工。

---

## 寫到哪

當前 repo 的 `.fledge/state.md`（目錄不存在就建）。**綁專案不綁票**——今天一張票都沒開、直接改了三小時 code，這裡照樣有東西。

**不進 git。** `.fledge/` 和 `.fledge/tasks/`（待辦票）同源，兩者都是**本機的工作狀態**，不是專案產出。內容常帶本機路徑、未 push 的 commit hash、臨時判斷，進版控只會製造與別人衝突的雜訊——所以**建議使用者**把 `.fledge/` 加進專案的 `.gitignore`。**這支 skill 不改 `.gitignore`**：發現專案沒排除 `.fledge/` 時提一句，加不加由使用者決定。

**代價講明**：換機器就沒了，沒有備份，誤刪救不回。這是已知取捨，不是漏做。

寫入是**覆蓋**，不是追加——它記的是「當前停在哪」，不是歷史。歷史交給 git log，不是這裡的責任。

---

## 兩級寫法，你自己判斷用哪級

| 級別 | 何時用 | 長度 |
|---|---|---|
| **精簡** | 一般收工（絕大多數情況） | 三五行 |
| **完整** | **一個階段做完、下一階段還沒開始** | 五個小節 |

分兩級的理由：完整版的價值很明顯（讓人隔幾天回來完全不用重新想），但如果每天收工都產 30 行，那些字很快就沒人看。

### 精簡版格式

```markdown
# <專案名> — 目前狀態

> 更新：<YYYY-MM-DD>

**卡在**：<一兩句，具體到檔案或函式>

**下一步**：<一句，要能直接動手的程度>

**坑**：<這個 session 踩到、下次要避開的東西。沒有就省略這行>
```

> **`**下一步**：` 這個標籤是與 Fledge 面板之間的格式合約**——面板的總覽表抽這一行
> 顯示在「下一步從哪起」欄。介面語言是英文時寫 `**Next**: `，兩種都認。
> 標籤必須在檔案的**前 20 行**內（面板只讀那麼多）。

### 完整版格式

完整版的骨架來自一份 34 行的實際案例——證明離場筆記需要結構，不是自由散文。

```markdown
# <專案名> — <階段名> 起手

> 更新：<YYYY-MM-DD>

**下一步**：<一句，要能直接動手的程度>

## 1. 載入什麼（實讀，別憑印象）
<要讀的 memory key、spec 檔、既有契約文件，附路徑>

## 2. 確認狀態
<分支／未 push／venv／DB／環境是否就緒。狀態事實全放這裡>

## 3. 完整流程
<下一階段的完整步驟，不是一句「繼續做」>

## 4. 工作慣例
<這個專案特有的規矩：審查指令全文、測試不得碰哪個 DB、驗收方式>

## 5. 新 session 要記得的事
<跨階段的伏筆、已知會踩的雷>
```

---

## 寫的時候注意四件事

1. **「下一步」要能直接動手** — 「繼續處理 i18n」不合格；「寫一支掃原始碼的檢查，確認所有靜態引用的 `errors.*` key 都存在」合格。
2. **狀態事實放這裡，不要另開待辦** — 「repo 尚未 push」「某測試目前 skip」會變、記成待辦只會過期，它們屬於「確認狀態」那節。
3. **具體到位置** — 卡在哪一個檔案、哪一個函式。下次回來要能直接跳過去。
4. **不要寫成事後回顧的敘事** — 那種寫法是給人看的總結；這裡是給下一個 session 用的前瞻。同一件事，兩種寫法。

---

## 順手做的第二件事：建票收網

寫完筆記後，**回顧這個 session 有沒有該建票而沒建的事項**。

理由：Beads 實測過的弱點是「長 session 會忘記 backlog 存在」——工作三小時後，一句 CLAUDE.md 規則早已不在注意範圍內。收工這一趟是天然的收網點。

判準：

- **該建**：現在不做、但不想忘
- **不該建**：五分鐘做得完的（直接做掉）、狀態事實（進上面第 2 節）
- **同類先合併**：同一個 session 發現的同類問題合成一張票帶多個子項，不要拆成三張

**怎麼建**：建票走 `fledge-tasks` skill（它管 `.fledge/tasks/` 的格式與編號）。但**不要自己動手開票**——
`fledge-tasks` 的規矩是「使用者沒開口就不開票」，這裡也一樣。把候選列出來給使用者看，格式：

```
這個 session 還有 N 件建議建票：
1. <標題> — <為什麼現在不做>
2. ...
```

使用者點頭的才開；沒裝 `fledge-tasks` 的話就只列，不寫任何檔案。
